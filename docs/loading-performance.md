# 重複開啟與同步效能（2026-11-05）

使用者在電腦登入同一 Google 帳戶後，每次重新整理／開啟仍等待很久。相同帳戶共用教材是預期行為；本次修正集中在重複下載與本機讀寫，不更動學習規則或資料庫結構。

## 問題與調整

- 原本登入初始化每次都等待完整雲端下載；已有同帳戶本機內容時，現在只等待 IndexedDB 載入便可使用，雲端檢查在背景進行。空的新裝置仍須完整下載，避免在資料未齊時建立錯誤學習計畫。
- 首次登入的 auth 事件、視窗 focus、visibility、手動同步及版本監看可能重疊觸發下載；同一帳戶／設定世代現在共用進行中的一次下載。同帳戶 token 更新不會因單例剛被資料通知清除而重新初始化。
- 完整且成功套用的快照保存帳戶範圍的雲端 revision。後續版本相同只查 revision、不再下載所有資料表；版本改變才重拉完整分頁。版本快取不納入完整備份，還原後會重新核對。既有跨帳戶、下載期間本機寫入及 outbox 變動的保護保留。
- `accountStorage.getItem` 原本透過 `readAccountSnapshot` 複製整個帳戶，連讀一個小偏好也會複製約 6 MB 的學習 store。內部字串讀取改用不暴露可變物件的參照；對外匯出的 snapshot 仍複製、不能改動內部 cache。
- 資料鎖原本即使只讀或存入相同值，也會再寫一次完整 IndexedDB／localStorage 副本。現在只在實際變更時保存；純讀不重寫資料。若讀取時發現另一分頁已提交新版，仍通知畫面刷新。真正寫入仍維持同一帳戶的原子快照、rollback、journal 與 FIFO 語意。
- PWA shell v36。
